# Security Policy

## Поддерживаемая версия

Исправления безопасности выпускаются для текущей версии ветки `main`.

## Сообщение об уязвимости

Не создавайте публичный issue, если находка может раскрыть токен, пользовательские данные, локальные пути или рабочий способ эксплуатации.

Используйте GitHub Security Advisory: **Security → Advisories → New draft security advisory**. Укажите:

- затронутую версию и компонент;
- минимальный сценарий воспроизведения;
- влияние и необходимые условия атаки;
- обезличенные логи;
- предлагаемую проверку исправления, если она известна.

Не присылайте реальные токены, содержимое `data/state.sqlite3`, журналы с идентификаторами пользователей или приватные сообщения. Если секрет попал в отчёт, сначала отзовите его через BotFather и только затем продолжайте расследование.

## Границы проекта

Особенно важны сообщения о:

- обходе безопасного AST-парсера;
- доступе одного пользователя к настройкам или callbacks другого;
- утечке токена или Telegram/SQLite данных;
- SSRF, подмене провайдера или небезопасном XML/JSON parsing;
- неконтролируемом потреблении CPU, памяти, сети или Telegram API;
- supply-chain изменениях launcher/зависимостей.

Ошибки цены без security-воздействия следует оформлять обычным bug issue с точными входными данными и временем наблюдения.
